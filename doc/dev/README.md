# 開發計畫管理規範 (Development Planning Workflow)

本目錄 (`doc/dev/`) 專門存放所有新功能、重大改動或架構重構的開發計畫文檔。

---

## 📋 開發工作流程原則 (SOP)

所有 AI Agent 與工程人員在執行功能開發時，**必須** 嚴格遵守以下四部曲：

```
[1. 需求討論] ──> [2. 計畫撰寫 (doc/dev/)] ──> [3. 批准與實作開發] ──> [4. 驗證與回寫規格 (doc/spec/)]
```

### 1. 功能開發前先討論
- 在動手修改程式碼前，先與使用者/產品負責人進行充分溝通與需求對齊。
- 釐清業務邊界、使用者角色（RBAC）、畫面互動形式與對現有資料結構的影響。

### 2. 撰寫開發計畫並存入 `doc/dev/`
- 依照 [`template_plan.md`](./template_plan.md) 範本撰寫詳細設計。
- **命名規則**：強制使用 `plan_<功能名稱>.md`（例如：`plan_rfi_pdf_export.md`、`plan_gantt_critical_path.md`）。
- 提交給使用者確認批准後，作為後續實作唯一的基準與依據。

### 3. 實作與遵循計畫
- 嚴格依照計畫內規劃的任務清單進行漸進式變更。
- 遵循專案既有之 Terminal/Cyberpunk 視覺風格與 TypeScript 型別定義。

### 4. 驗證並回寫規格至 `doc/spec/`
- 開發完成後執行 `npm run lint` 與 `npm run build` 確認品質。
- **強制步驟**：將新增或修改的資料實體、API 端點、工作流程、UI 規格，按章節更新回寫至 `doc/spec/`。
