# 第 04 章：RBAC 權限矩陣與稽核軌跡 (RBAC & Security)

本章規範 PMS 系統內建之角色型存取控制 (Role-Based Access Control) 與防竄改稽核軌跡機制。

---

## 4.1 使用者角色定義 (User Roles)

系統支援雙層角色判定（全域系統角色 `systemRole` 與 專案成員角色 `projectRole`）：

| 角色名稱 | 代碼 | 職掌定位 |
| :--- | :--- | :--- |
| **系統總管 (Admin)** | `admin` | 系統最高權限，可管理所有專案、成員資格、資料庫重設與系統配置 |
| **專案經理 (PM)** | `pm` | 專案總負責人，掌控時程里程碑、核准 RFI 決策、調整看板階段與 WIP 限制 |
| **工程團隊 (Member)** | `member` | 現場主任、監造工程師、建築師，可新增/拖曳任務、提請 RFI、上傳圖說附件 |
| **訪客觀察 (Viewer)** | `viewer` | 業主代表、第三方查核員，僅具備唯讀權限，不可修改任務或發布 RFI |

## 4.3 系統稽核日誌機制 (Audit Trail)

### 1. 紀錄原則
系統所有會造成狀態持久化更動的操作，皆會自動生成一筆不可竄改的 `AuditLog`。

### 2. 紀錄屬性包含
- `timestamp`：精密至毫秒的 ISO 8601 時間戳記。
- `userId`：執行該項變更之使用者 ID 與姓名。
- `action`：動作關鍵字（如 `MOVE_TASK`, `ANSWER_RFI`, `CREATE_TASK`, `UPDATE_PROJECT`）。
- `targetType` & `targetId`：目標實體類別與主鍵。
- `details`：變更前與變更後之數值對比或操作備註。
